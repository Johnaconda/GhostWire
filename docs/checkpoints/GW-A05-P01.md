## 2. Main decisions and protocol separation

- **Proposed** strict RFC 8949 deterministic CBOR profile behind a 4-byte
  unsigned big-endian length prefix, with frame ceiling 65,536 bytes, exact
  key registry, preferred encoding, no indefinite lengths, unknown fields or
  unsupported versions and no unbounded recursion/allocation. A05-P02 must
  independently review and select a pinned decoder/library before code.
- Major/minor negotiation types 1/2 and A04 public DeviceSet carrier type 10
  only. Reserved authentication proof type 20 and encrypted container type 30
  reject. Capability lists must be empty at proposed 1.0. No cryptographic
  suite negotiation is approved or implemented.
- A04 `GhostWire.DeviceSet.v1\0` signing bytes, suite=1 Ed25519, authority
  validation, scope, revision and trust pins remain unchanged. Valid syntax
  does not imply trust, current private-key possession, membership admission or
  permitted actions. The routing token never selects a principal.
- Negotiation is unauthenticated advisory data. A future approved authentication
  mechanism must prove fresh possession and bind offers/selections/suites to
  an authenticated transcript before making security claims. No unreviewed
  handshake, crypto primitive, DM or MLS protocol is introduced.
- Strictly bounded staging values and fixed diagnostic categories are specified
  without introducing build targets, headers, incomplete API stubs or workers.

## 4. File scope, preservation and packaging

All C++ production sources/headers, CMake targets/presets, Botan and doctest pins,
CLI behavior, older test definitions, signed A04 record data and runtime version
remain byte-identical to accepted P03. Changes are documentation, JSON/CDDL
fixtures, a *documentation-only* consistency checker and the allowlisted
source-packaging script. `SOURCE_MANIFEST.json` is regenerated automatically;
see [exact changed-file inventory](GW-A05-P01-CHANGED-FILES.md).

The deterministic source ZIP is one `GhostWire/` root including all earlier
history and third-party pinned source distributions. The external SHA-256 sidecar
is not embedded (would be self-referential). Generated builds/caches, secrets
and Git metadata are excluded. The package is **not** remotely published.

## 5. Known limits and acceptance gate

- CDDL is a schema skeleton; its body union alone cannot enforce kind-specific
  discriminators, canonical encodings, semantic range/capability policy or the
  independent A04 signature/trust state. Normative prose is required in P02.
- The proposed CBOR dependency is not yet pinned. No upstream vulnerability,
  license, parser allocation or third-party implementation review is implied.
- Cross-platform binary reproducibility of future codec bytes has not been
  tested because no codec exists. Future E2EE, transport authentication,
  replay and privacy policy need separate accepted security designs.
- P03 hosted GitHub green workflows do not establish P01 source CI acceptance.
  Unchanged C++ file bytes and passing local Debug build do not replace owner
  Windows acceptance.
