## Implemented functionality

- Explicitly owned volatile profiles with independently generated Ed25519 root
  and device keys. Equal numeric aliases never merge identities. Strict bounded
  UTF-8 display names and generation/owner-checked opaque handles preserve scope.
- Independent profile/community membership authorities and devices; explicit
  community pins and preparation are not remote admission or permissions.
- Typed domain-separated SHA-256 IDs and bounded canonical complete DeviceSet
  records, signed and verified through the existing pure Ed25519 provider.
  Version, suite, purpose, scope, authority, lengths, ordering and UTC validity
  are checked; arbitrary signing and private-key import/export are absent.
- Explicit per-profile pins, acceptance, independent-verification state,
  blocking, forgetting and conflict resolution. Replay high-water marks,
  idempotence and equivocation rules do not silently adopt incoming trust.
- Scoped device addition, replacement, revocation and renewal. Recognition
  rechecks current records, block/conflict state and half-open time intervals.
  Local self-recognition observes owned revocation immediately; other isolated
  profiles must explicitly accept the changed public record.
- Injected clocks/provider, cooperative stop/deadlines, staged publication and
  cleanup, bounded profile/key/device/trust/public-byte admission. A UTC rollback
  beyond five seconds latches untrusted time until explicit local revalidation;
  this never resets revision or conflict state.
- A separate composition adapter registers identity after CryptoService and
  destroys identity consumers before provider teardown. One logical capacity
  reservation is held until stop. No detached threads or work queue were added.
- A real opt-in `ghostwire-cli --identity-session` command console provides
  creation, selection, labels, membership preparation, public inspection,
  device changes and explicit profile trust/recognition. `help` documents the
  grammar. Quit/EOF clears keys and trust; a new session starts empty.

`ghostwire_identity` depends on crypto and header-only core clock/result
contracts; `ghostwire_composition` connects core lifecycle and identity. There
is no core-to-identity implementation edge or permissions cycle. All four
ordinary executable bootstrap/configuration/path/exit contracts remain covered.
Normal startup never creates an identity. Dependencies and compiler warning
policy are unchanged. Architecture, module/security contracts, roadmap, TODO,
changelog and completed-work records accompany this implementation.

## Security and operational limitations

A11-PRE and AUTH-PRE remain intact. No persistence of profiles, private keys,
trust, recovery or private mappings; no listeners, networking, GUI, messaging,
remote enrollment or AI functionality. All identity state is deliberately lost
on shutdown. No new private backup/cache/index/temp-file path was introduced.
OS swap/crash-dump exposure and hostile same-process memory access remain outside
this volatile service's guarantees; no process sandbox or secure vault is claimed.

Signed public records establish local cryptographic consistency and scoped
recognition, not live possession, remote login, community admission, action
permission, network revocation distribution or production E2EE. Root continuity
and recovery remain deferred. Monotonic deadlines are cooperative checks around
provider calls, not preemption of a stalled primitive. Services are owner-thread
objects. Budgets reserve declared logical key/public-frame capacity, not measured
RSS, CPU headroom or all provider/allocator overhead. No performance claim follows
from test timings.

The CLI's `show` commands deliberately disclose public identity information to
the terminal; ordinary diagnostics remain fixed counts/enums. Input is bounded
and has no application history file. Quit/EOF is the supported clean shutdown;
Ctrl+C during blocked synchronous stdin is not guaranteed graceful. Membership
CLI pinning and preparation are two explicit operations: a preparation failure
retains the already-created pin and reports this. No private import/export or
arbitrary signing command exists.
