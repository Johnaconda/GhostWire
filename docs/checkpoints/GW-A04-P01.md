## Security, limitations and pending decisions

No new runtime attack surface or private persistence. A11-PRE and AUTH-PRE stay
mandatory. The design never treats aliases, hardware or IPs as ownership; valid
signatures do not automatically grant trust, live possession or application
permissions. Proposed per-community keys do not promise anonymity. Public signed
bytes exclude private profile metadata; A03's public-message-only Ed25519 contract
and memory limits remain unchanged. No new primitive, DM/group protocol or remote
authentication handshake is selected or implemented.

Owner review is requested for the concrete hierarchy (profile root/device plus
per-community membership authority/device), full scoped identity under colliding
aliases, and the bounded first implementation: volatile state, working device
replacement/revocation, deferred root continuity/recovery. No general two-factor,
permanent identity, multi-device synchronization or durable rollback guarantee.

The user's personal Mac is unavailable; hosted native tests are now positive
evidence, not a fabricated host result. Older macOS versions/physical hosts,
owner-local Windows vcpkg configuration, local full LSan, clang-tidy and independent
crypto review remain distinct limits. Hosted Linux Release has an observed Botan/
GCC diagnostic queued for triage; no warning policy was weakened.
