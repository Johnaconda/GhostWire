## Explicit upstream fetch and test path

On a machine with HTTPS access, from the extracted source root:

```sh
python tools/protocol/fetch_tinycbor.py --acknowledge-network --output tinycbor-v7.0-pinned.zip
python tools/protocol/import_tinycbor.py --source tinycbor-v7.0-pinned.zip --install
cmake -S . -B out/tinycbor-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DGW_A05_ENABLE_TINYCBOR_INTEROP=ON
cmake --build out/tinycbor-debug --target ghostwire-protocol-probe ghostwire-tinycbor-probe
ctest --test-dir out/tinycbor-debug -R '^(protocol-tinycbor-interop|protocol-tinycbor-stdin-bounds)$' --output-on-failure
```

The downloader intentionally cannot be activated by the normal build. It
requires both command-line acknowledgement and a new output path. The saved ZIP
is an operator-supplied **source input**, not a binary artifact, and is not
included in this distribution. The pinned test-only TinyCBOR subset is licensed
MIT and must retain its upstream license when actually bundled.
