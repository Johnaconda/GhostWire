## Integration and worker model

Three isolated source worktrees were based on the same hash-verified 240-file cumulative source. Their source edits did not overlap. Task-focused tests ran in each worktree. The deterministic, offline delivery merger then checked an exact common baseline manifest, file SHA-256 digests, ownership collisions and unsafe paths before creating a fresh integrated source root.

No independently spawned AI coding agents were available in this environment. Task authorship was centralized; independent *processes*, source worktrees and validation jobs were used. The coordinator remains responsible for integration and correctness. `docs/development/WORKER_QUEUE.json` records workstream ownership, next dependencies and subjective confidence estimates.

## Delivered changes

1. **Codec admission:** precompute closed-grammar serialized lengths and check frame/work budgets before any buffer allocation. Verify emitted size exactly equals preflight prediction, fail-closed on mismatch. Expanded roundtrips across CBOR 255/256 byte-string header transition, optional routing and exact byte/work ceilings.
2. **Offline source import:** validate regular file type, reject symlinked input ancestors, deny nonnormalized and mixed-root ZIPs, case-fold collisions and suspicious archive member types. Expanded negative and positive synthetic tests.
3. **Offline worker merger:** accept only disjoint checksummed worker deliveries with the same baseline manifest, verify all existing baseline file hashes, reject traversal/case collisions/symlinks/stale submissions, and stage integrated output atomically without executing worker-supplied code. A separate test exercises malicious and overlapping submissions. `development-worker-merge` is registered with CTest when Python is available.
