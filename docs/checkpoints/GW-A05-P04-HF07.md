## Windows 10% acceptance findings

The owner's VS2026 CTest run listed 50 Windows registrations but found that
most test executables had not yet been compiled. Running the CLI target in
Visual Studio **does not** build all CTest targets. Run `cmake --build --preset
portable-debug` (and Release) before CTest. Missing executables are not
assertions about GhostWire behavior.

A real portability issue was found in `test_tinycbor_import.py`: Python's
`zipfile.writestr()` normalizes backslashes on Windows while constructing a
ZIP member, so a supposed malformed test entry was actually valid. The test
now creates a valid ZIP and replaces the on-disk local/central directory
member bytes with a same-length malformed backslash name. The importer
explicitly rejects source member names that the ZIP library normalized,
using `ZipInfo.orig_filename` as a separate check before parsing the path.
It never extracts untrusted ZIP members.
