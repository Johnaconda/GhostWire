# GW-A05-P04-HF03 — Canonical verdict gate / source publication hardening

**Input:** The cumulative A05-P04-HF02 source, archive SHA-256

acceptance can follow but is not simulated. Runtime remains `0.4.1`.

## Changes

1. The optional independently executed TinyCBOR probe is not enough merely to
   accept frames that GhostWire accepts. It must **also reject** five frozen
   A05-P01 generic-CBOR-noncanonical examples: duplicate top-level key,
   duplicate nested key, out-of-order top-level keys, nonpreferred integer
   width, and indefinite map. This is intentionally separate from
   GhostWire-only invalidity (e.g. unsupported registered message versions)
   which a generic maintained CBOR parser must accept for the five frozen
   explicit controls: wrong major/minor version, reserved kind, nonempty
   capabilities, unknown top-level key.
2. An offline 16-check comparator fault harness ensures all-positive,
   all-negative, nonsensical, missing and canonical-bypass verdicts cannot be
   reported as passing optional interoperability. This tests **our test
   checker**, not TinyCBOR. CTest registration is independent of any upstream
   import or network access.
3. Verified test-only importer publication now rejects dangling symlinks at
   its destination as well as existing paths; synthetic import regression
   covers first publication, existing directory refusal and broken symlink.
   This is an offline cooperative-build atomic rename workflow. It does **not**
   defeat a hostile process concurrently racing modifications in the same
   writable directory. Secure destination ownership is still necessary.

## Security boundary and outstanding gate

This does not modify the production codec, A04 signing/trust, wire schema,
private-key handling, runtime version, or link any maintained CBOR parser into
shipping binaries. Test-only source acquisition remains explicitly opt-in.
**A real pinned TinyCBOR library compile and 4,023+ input comparison remain
UNRUN unless separately evidenced.** Source pins and verifier tests cannot
replace this gate. No public network inputs, A06 networking, authentication,
E2EE, vault, GUI or remote authorization are enabled or approved.
