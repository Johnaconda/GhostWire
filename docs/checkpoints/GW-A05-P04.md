## Authoritative baseline and changes

Input: `GHOSTWIRE-GW-A05-P03-CODEC-SECURITY-AND-DIFFERENTIAL-source.zip`, SHA-256
`3f83e94a0d2852eea2bd824e265e2854a3abcdbff5fe0d07336cf2be564086b6`.
No GitHub writes. The published `main` remains an earlier A04-P03 baseline; these
cumulative A05 files must not be replaced by a GitHub checkout.

Implemented in this candidate:

1. Independently confirmed TinyCBOR v7.0 tag commit
   `6442e749ca811e24afad1551338a45c75e09808f`, source tree paths,
   per-file SHA-256 hashes and MIT license via GitHub's read-only interface.
2. Added a strict **offline** source verifier for a separately supplied TinyCBOR
   source ZIP or extracted tree. It validates 12 pinned original files, exact
   lengths and SHA-256 hashes, archive CRC, unique safe paths, symlink denial,
   bounded total size and a single upstream ZIP root. `--install` stages all
   verified files atomically under `third_party/tinycbor/verified/`.
3. Added an **opt-in test-only** CMake target controlled by
   `GW_A05_ENABLE_TINYCBOR_INTEROP`. It refuses to configure unless the exact
   pinned upstream files have been imported and reverified, then compiles the
   maintained C parser in a separate static library and links only an isolated
   stdin/stdout validation probe. No product role or `ghostwire_protocol` links
   the upstream parser. This target has not yet been compiled on actual upstream
   source in this checkpoint.
4. Extended the seeded 4,005-frame differential harness to optionally classify
   maintained-parser results independently. Accepted GhostWire canonical frames
   MUST pass upstream canonical validation; valid general CBOR may still fail the
   stricter GhostWire closed schema. No parser verdict grants authority.
5. Added an isolated C++ allocation-fault process that injects `std::bad_alloc`
   into encode and public-record decode, verifies typed `resource_limit`,
   restoration of the admission lease and recovery on the next call.
6. Added a fail-closed importer regression suite for tampering, ZIP traversal,
   duplicate paths and valid test sources. Runtime remains `0.4.1`.

## Outstanding blockers — do not close these by inference

- The pinned upstream source ZIP could not be copied into this environment via
  the available GitHub read-only interface, and direct sandbox network download
  is disabled. **No actual upstream source is vendored in this ZIP.** Therefore
  the opt-in C target, maintained-library comparison and its portability remain
  **unrun**, not PASS. An import/check script does not substitute for this gate.
- No actual MSVC Windows P02/P03/P04 or macOS P04 logs are supplied. The existing
  owner request to continue is not reproducible native acceptance.
- A bounded test-only maintained parser is not necessarily approved for product
  wire parsing. ADR-010's hand-authored cursor exception and ADR-009 design
  dependency decision require independent code/security review before any
  network exposure or replacement of the codec. Full native sanitizer,
  memory-pressure, fuzz and interoperability work remains open.

## Ownership/security

There is no socket, listener, private persistence, account vault, protocol
login, E2EE, discovery, remote authorization, GUI or AI feature. Only the
three previously registered public message kinds can be decoded. No A04
signed DeviceSet bytes or identity trust rules changed. Upstream import is
never implicit, and the default self-contained build needs no new dependency.
The finite cursor remains non-network-approved. Validation verdicts are not
authentication, authorization, negotiation transcript proofs or downgrade
resistance.
