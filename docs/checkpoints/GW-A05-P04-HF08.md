## Reproduction and evidence limits

Owner Windows 10 x64 / VS2026: **49/50 Debug CTest**, with
`protocol-allocation-fault` timing out at its existing **15-second watchdog**.
Other tests (including the TinyCBOR importer) passed. HF07 Release Windows
validation was not reached. The original unmodified HF07 fixture passed on
local GCC 14.2 Linux Debug in 0.02 seconds. **No Windows debugger stack or
native reproduction was available here, so an MSVC root cause is not proven.**

The old fixture replaced *process-wide* global `operator new` and `operator
new[]`, intercepting allocations by everything in the test process including
compiler-runtime/library machinery. This is an avoidable platform-specific
harness risk; it is not evidence by itself of a deadlock in the codec.

## Exact correction

- In the fault test executable **only**, compile the real `wire_codec.cpp`
  separately under private `GW_PROTOCOL_FAULT_TESTING=1`. Keep the normal
  `ghostwire_protocol` target untouched and uninstrumented, with no hook
  symbol, new runtime dependency or new public header/API.
- The fixture defines a single test-only function invoked immediately before
  the two byte-buffer allocation sites (encode's `reserve`, decode's
  DeviceSet `assign`). It deterministically throws `std::bad_alloc` once;
  the original codec catches it and maps to `resource_limit` while releasing
  the caller-owned admission lease.
- Remove all global `operator new/delete` replacements from the fixture.
  This prevents the harness from inadvertently intercepting MSVC CRT
  allocations or exception-handling machinery.
- Preserve strict budget preflight assertions (zero byte-buffer allocation
  attempts), exact error classifications, two injected faults, successful
  recovery/roundtrip, unchanged caller data, and admission lease cleanup.
  The hook measures **codec-owned buffer allocation boundaries**, rather
  than every possible unrelated C++ runtime allocation; this measurement
  difference is intentional and disclosed.
- Preserve the **original HF07 global allocator harness** as a separate
  Linux-only regression, `protocol-global-allocation-linux`, where it is
  confirmed to work. This retains whole-process preflight allocation counting
  and genuine `operator new` exception recovery *in addition to* the portable
  test-only injection mechanism. Do not run the global override test on MSVC
  or sanitizer presets, where overriding compiler runtime allocations can
  introduce false hangs or instrumentation conflicts.
- Keep the **15-second CTest timeout** unchanged on both fault fixtures. No
  assertions are skipped, and no failure is reclassified as a pass.
