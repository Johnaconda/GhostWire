The build then failed at `tests/fixtures/protocol/allocation_fault.cpp:24`

## Smallest correct change

- `src/protocol/wire_codec.cpp`: declare the **test-only** allocation hook
  with C++ linkage and `noexcept(false)` rather than `extern "C"`.
- `tests/fixtures/protocol/allocation_fault.cpp`: define the same C++
  linkage function with `noexcept(false)` and document why it must throw.
- Keep `/EHsc`, `/WX`, fault injection, deterministic assertions and the
  existing 15-second watchdog. No blanket warning suppression, disablement,
  changed resource-limit semantics or runtime ABI modification.
- Only the separately compiled `GW_PROTOCOL_FAULT_TESTING=1` executable
  links this hook; the production protocol target remains uninstrumented.

C++ linkage is the appropriate contract for a test function that intentionally
throws `std::bad_alloc` into C++ codec exception handling. Under MSVC's `/EHsc`
(`/EHs /EHc`) assumption, `extern "C"` functions are assumed not to throw,
causing C4297 under `/WX`.
