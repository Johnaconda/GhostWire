## Changes

1. **Security finding P03-F01, fixed:** `selected_was_offered` accepted an impossible caller-authored local offer containing both `[1,0]` and unsupported versions (or duplicate `[1,0]`) despite the registry allowing precisely one version. It is advisory only; this was no authenticated bypass, but could lead to inconsistent future negotiation if reused. Now requires the exact v1.0 offer `[1,0]`, empty capabilities and exact selection. Added focused regression.
2. Added a test-only `ghostwire-protocol-probe` process that accepts bounded hex input via stdin and calls the **real** in-memory decoder; it emits fixed error codes or exact canonically re-encoded bytes. It neither opens sockets nor touches identities. It is never a privileged parser, product CLI, or protocol service.
3. Added a separate seeded Python AST/serializer-vs-C++ differential checker with deterministic structural positive and malformed byte mutations. It exercises the actual codec over subprocess stdin; no invented expected bytes from its encoder alone qualify as an oracle. Python reference implementation is separate source from the C++ cursor, **but is not a maintained upstream CBOR library**.
4. Updated testing/roadmap/checkpoint records, Windows acceptance and next proposal. No new dependencies, external libraries, cryptography, private keys, identity mutations, persistent state, sockets, network exposure or AI runtime features.

## Independent external parser research and gate

Pinned upstream candidates for a future offline audited adapter:

- QCBOR **v1.6.1**, upstream commit `930708bb86481e88879eb1d87fd4d664f1d69503`; mixed BSD-3-Clause and modified BSD-3-Clause notices according to upstream LICENSE, requiring per-file retention. https://github.com/laurencelundblade/QCBOR/tree/v1.6.1
- Intel TinyCBOR **v7.0**, upstream commit `6442e749ca811e24afad1551338a45c75e09808f`; MIT LICENSE. https://github.com/intel/tinycbor/tree/v7.0

Refs and LICENSE contents were directly inspected. Neither library was downloaded, compiled, vendored, or linked in this checkpoint. Their full API/runtime parser profile, strict duplicate and canonical map enforcement, Windows/MSVC implementation portability, exact license inventory and negative corpus **remain unverified**. Python AST differential testing must not be misreported as QCBOR/TinyCBOR interoperability. RFC 8949 deterministic encoding requires preferred widths, indefinite-length rejection and map key ordering; GhostWire's closed 0..23 integer keys trivially preserve canonical key ordering but still require the full review gate. Library migration is a separate, authorized patch once source can be audited and retested. Network exposure stays forbidden.

## Security boundary review

- **Accepted framing/grammar invariant:** only big-endian four-byte exact length, deterministic definite CBOR, hard 65536-byte frame ceiling, closed keys, kinds 1/2/10, cap lists empty; unknown or auth/E2EE kinds are rejected. No recursive deserialization or unknown-field skipping is introduced.
- **Admission and work:** caller-owned atomic operation lease; bounded work, time/cancel at checks and just before publication. Failures own no published decoded result. No parser allocation based on unchecked CBOR length. The public `Admission::release` contract still assumes sole ownership; misuse from another thread is outside its documented concurrency API. No claims of preemptive cancellation during a single large allocation.
- **A04 trust:** public DeviceSet payload is carried unchanged and checked separately by A04 signing/authority/expiry/revision routines. The codec must never select a principal, membership, permission or trust pin from a routing hint or displayed alias.
- **Logs:** ErrorCode contains only fixed categories; test probe emits integers or public wire bytes to its controlled stdout, and must not be exposed to untrusted logs.
- **Negative coverage:** no evidence of dynamic-allocation failure injection, independently maintained parser interoperability, Windows sanitizer, 32-bit correctness, local LeakSanitizer or independent security certification. Explicitly residual gates, not silent successes.

## Parallel execution model used

No independent AI subagent/worker-spawning interface was available in this session. Work was partitioned into separately launched operating-system processes with isolated build directories and logs: `gcc-debug` full build/CTest/differential, `gcc-release` full build/CTest/differential, and `clang-asan` protocol-focused sanitizer/differential. A separate libFuzzer process and source/fixture checks were also used. These are real concurrent **validation jobs**, not independently reasoning or coding agents. Code integration and conflict handling remained a single responsible editor, avoiding misleading multi-agent provenance. The exact results are in P03-VALIDATION.json and accompanying worker logs are not shipped with the source.

## What this checkpoint cannot establish

A codec parsing untrusted bytes successfully is not peer authentication, secure channel negotiation, downgrade resistance, confidentiality, replay protection, server authorization or identity acceptance. The controlled ADR-010 parser exception remains unresolved for public network inputs. This checkpoint does not authorize A06, AUTH-PRE bypass, A11-PRE bypass or production use.
